## 1. Loopback Listening Proof (Evidence E2)

Verify that both the FastAPI backend and the Ollama inference server are listening exclusively on the loopback adapter (`127.0.0.1`), with zero external/LAN exposure.

### Windows Command:
```powershell
netstat -ano | findstr "8000 11434"
```
**Expected Output:**
```text
  TCP    127.0.0.1:8000         0.0.0.0:0              LISTENING       [PID]
  TCP    127.0.0.1:11434        0.0.0.0:0              LISTENING       [PID]
```
Ensure that neither service shows `0.0.0.0:8000` or a LAN IP like `192.168.x.x:8000`. Save output to `docs/evidence/e2_listeners.txt`.

## 2. Windows Firewall Outbound Blocking Rules (Evidence E3)

For defense-in-depth verification while connected to an enterprise network, apply per-program outbound firewall blocks.

### Step 2.1: Add Blocking Rules (Run PowerShell as Administrator)
```powershell
# Resolve paths to your Python virtual environment and Ollama executables
$PythonExe = (Resolve-Path ".venv\Scripts\python.exe").Path
$OllamaExe = (Resolve-Path "$env:LOCALAPPDATA\Programs\Ollama\ollama.exe").Path

netsh advfirewall firewall add rule name="SAW block python" dir=out action=block program="$PythonExe" enable=yes
netsh advfirewall firewall add rule name="SAW block ollama" dir=out action=block program="$OllamaExe" enable=yes
```

### Step 2.2: Verify Firewall Rules
```powershell
netsh advfirewall firewall show rule name="SAW block python"
netsh advfirewall firewall show rule name="SAW block ollama"
```
Save the listing to `docs/evidence/e3_firewall_rules.txt`.

### Step 2.3: Delete Rules (After Testing)
```powershell
netsh advfirewall firewall delete rule name="SAW block python"
netsh advfirewall firewall delete rule name="SAW block ollama"
```

## 3. Wireshark Network Traffic Capture (Evidence E4)

Prove that no network packets leave the workstation during full workflow execution (Demo A / Demo B / Demo C).

### Step 3.1: Start Capture
1. Launch **Wireshark**.
2. Select your **active physical interface** (e.g. `Wi-Fi` or `Ethernet`).
   *(Do NOT select the loopback adapter; the air-gap guarantee is that zero packets escape onto the physical network).*
3. Start the capture and record the start timestamp.

### Step 3.2: Run the Workflow
In the Sovereign AI Workbench UI:
1. Run **Demo A** (Process scanned inspection PDF, OCR, Gemma 4 vision analysis, RAG SOP-301 retrieval, AST calculations, and DOCX generation).
2. Wait for completion and review gate status (`PENDING_REVIEW`).

### Step 3.3: Apply Wireshark Display Filters
In Wireshark's filter bar, test each of the following filters:
- `dns` — Must show zero DNS queries generated by Python or Ollama.
- `tls` — Must show zero TLS handshakes to external cloud endpoints.
- `tcp.port == 443` — Must show zero outbound HTTPS traffic from the workbench.
- `!(ip.addr == 127.0.0.1)` — Filters out any loopback packets; must reveal zero outbound workbench traffic.

### Step 3.4: Save Evidence
1. File -> **Save As...** -> `docs/evidence/e4_traffic_capture.pcapng`.
2. Take screenshots of the filtered Wireshark window showing zero packets and save to `docs/evidence/e4_wireshark_zero_traffic.png`.
